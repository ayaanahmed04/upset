history, a two-fighter comparison, detailed recorded stats, an experimental

## Start the server on the Mac

```zsh
cd ~/Projects/upset
./Start\ UPSET.command
```

Open [the Mac viewer](http://127.0.0.1:8768/#/). Leave Terminal open while using
UPSET. Ctrl+C stops a viewer started in that window. The launcher is executable
and can also be opened from Finder. If the port is occupied, check the viewer
and its footer before starting another process.

For a phone on the same home Wi-Fi, run this in a second Terminal window.

```zsh
cd ~/Projects/upset
UPSET_BIND_HOST=192.168.4.75 UPSET_PORT=8769 ./Start\ UPSET.command
```

Open [the Wi-Fi viewer](http://192.168.4.75:8769/#/) on the phone. The Mac's
Wi-Fi IP was `192.168.4.75` on November 10. If it changes, use the value from
`ipconfig getifaddr en0` or macOS Wi-Fi settings in the command and URL.
The `127.0.0.1` address always refers to the device opening it.

Ports 8768 and 8769 are separate processes. Starting or refreshing one viewer
leaves the other process on the dataset it already loaded. On November 8 the
Mac viewer was updated first and the Wi-Fi viewer briefly showed Walker's
previous fight. Both were switched to the November 8 release. When installing
a new data release, check every running UPSET listener. Confirm the newest
bout date in the footer and the new fight in both participants' histories.

```zsh
lsof -nP -iTCP:8768 -iTCP:8769 -sTCP:LISTEN
```

## How ratings and stats work

- Recorded stats describe actual fights. The significant-strike preview
  estimates how often a fighter lands using recent UFC history and adjusts
  toward a population rate when there are few attempts. Select Career to see
  it. The estimate is experimental,
  appears separately from recorded accuracy, and has no opponent adjustment
  or validated uncertainty ranges. See
  [the striking preview notes](STRIKING_EXPERIMENTAL_PREVIEW_2026_11_04.md).
- Experimental v4 combines UFC résumé and skills equally. Skills combine the
  best, second and third of striking, wrestling and grappling at 50%, 30% and
  20%. The raw combined score is mapped to a 60–99 display scale. The display
  includes limited-history rules, a five-point limit per fight date and holds
  that prevent a win from lowering the badge or a loss from raising it.
- V4 widened the bands from 90 upward to smooth jumps around the low 90s.
  Pereira's Potieria win moves him from 89 to 92 in v4, compared with 89 to 94
  in v3. On the November 8 replay, jumps of four or more fell from 87 to 9 in
  the fixed cohort of 363 modest underlying updates near those grades.
  The higher badge won 1,772 of 2,954 shared historical comparisons in both
  versions. Treat that as historical evidence. Fresh prediction validation
  remains open. See [the v4 protocol](OVERALL_RATING_PROTOCOL_V4.md) and
  [the v4 walkthrough](OVERALL_RATING_V4_2026_11_06.md).
- Gaethje's win over Topuria moved his v4 badge from 88 to 89 and Topuria's
  from 96 to 94. Oliveira fell from 96 to 94 after the Topuria loss, then
  reached 97 after beating Gamrot and Holloway. These are useful cases for
  checking how readers interpret a résumé and skills grade beside a recorded
  fight result. The saved review packages under `docs/share/` cover earlier
  versions. Use the current v4 evaluation and protocol for the current release.

## How to update a card safely

1. Get the actual Cito event slug and confirm the completed card against UFC
   results. The configured key was usable on November 8. It lives in the
   project's local environment. Keep credentials out of chat, output and
   backups. Cito documented a rolling 30-day window for detailed bout and
   round stats on the free plan. Check the source and current plan limits
   when doing the next fetch.
2. Save the source responses to a new dated folder. The last card used
   `.venv/bin/python -m upset.data.collect_cito_card --event ufc-fight-night-november-07-2026 --output data/raw/cito_walker_2026_11_08_v1`.
   Use a new event and output for the next card.
3. Reconcile fight totals against the round rows and check both participants,
   winners, methods, round clocks and identity links. Preserve the prior
   database and stats. Admit older held bouts only after reviewing the saved
   data and identity evidence. The dated precedent is
   `scripts/import_walker_card_2026_11_07.py`. It contains that card's reviewed
   mappings and results. Build a new reviewed archive and SQLite database.
4. Rebuild the matching rating and striking artifacts for the new database.
   The November 8 order was `upset.ratings.build`, `build_v2`, `build_v3`
   candidate, `build_v3_refined`, then `build_v4`. Separately run
   `upset.skill.striking_preview` with the verified study in
   `data/processed/striking_rolling_2026_11_04_v1` and the new database and
   registry. Consult the builders' `--help` and preserve all existing
   artifacts. The rating and striking manifests bind the database and inputs
   by hash and path. A mismatched pair can cause startup failure or missing
   values.
5. Test the normal launcher on a temporary loopback port with the new release.
   Check the date cutoff before and after the card, a later date without bouts,
   search and history for new fighters, paired stats, comparison, rating
   badges, striking estimates, portraits and pending coverage. Then update
   the default release and restart the verified Mac and Wi-Fi listeners.
   Verify the live URLs before reporting completion.

The main entry point is `src/upset/research_app.py`. The default UI is
`src/upset/web/research.html`. Rating rendering is in `research_rating.js`
and `research_rating.css` in that web directory. Belt rendering is in
`research_champions.js` and `research_champions.css`. The separate editorial
design has its own files. Recent checks included the card import, rating
integration and striking preview pytest modules and
`node tests/research_ui_checks.cjs` and `node tests/rating_ui_checks.cjs`.

## Current priorities

beta, package a portable release, verify one complete card update on the
hosted staging build, and confirm rights for the public data and portraits.
The pending coverage and latest-data date should stay visible. The launcher
and snapshot manifests currently rely on the local filesystem, so verify
the deployment from an independent install.

result near the badges in a comparison and prospectively compare v4 against
a simple results-only baseline and a variant that gives more weight to
recent wins over strong opponents. These are proposals. The current
comparison still uses the existing rating and recorded stats views.
